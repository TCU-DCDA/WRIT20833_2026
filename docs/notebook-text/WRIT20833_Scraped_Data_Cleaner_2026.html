Before You Clean: What Did You Collect?

A scraper reads a page the way your browser shows it. So it grabs whatever was on screen: the posts or reviews or comments you wanted, but also usernames, profile links, "Reply" buttons, timestamps like "3d," and anything else that sat in the same box on the page. - Scrapers collect people, not only text. Your file probably has usernames, display names, or links to profiles. You don't need them to study what was said, so in Step 4 you'll leave them out. Keeping them would turn your dataset into a list of people who never agreed to be in it. - You got what loaded, not what exists. Infinite scroll, "load more" buttons, the site's own ranking, and whether you were logged in all shaped what reached your screen. That's your sample, and your writeup should say how you got it. - Long texts may be cut off. If the page showed "…See more," the scraper usually saw only the shortened version. Cleaning can't bring back words that were never collected. If most of your texts end in "…," it may be worth scraping again after expanding them.

Check Two Rules, Not One

Pandas 01 showed you how to read a site's robots.txt. That file is the site's rule for programs. The terms of use (usually linked at the bottom of every page) are the site's rule for you, and the two can disagree. Rotten Tomatoes is a real example. Its robots.txt doesn't block its review pages, so a robots-only check says "go ahead." Its terms of use say the opposite: no "robots, spiders, crawlers, devices, scripts or other data gathering or extraction software" to "scrape, data mine, or aggregate any content." A browser-extension scraper is that kind of software. What to do: 1. Check both. Open the terms and search the page (Ctrl+F or ⌘F) for scrape, robot, automated, and data mining. 2. If the terms allow it, or the source is built for collecting (like the YouTube API in the Comment Collector, or a published dataset), go ahead. That's the better path when one exists. 3. If the terms forbid it, and you have a real reason to study this site, you may go ahead for this class on four conditions: - Small: one scrape of what you could read yourself by scrolling, not a tool crawling page after page. - Private: the raw file stays in your own Drive and your submissions. No public GitHub, no shared links. - No people: leave out usernames and handles (Step 4 shows how). - Said out loud: your methods section names the site's rule and explains why you went ahead. 4. Not sure what the terms mean? Ask before you build on the data. This is the course's question in a new place: who wrote these rules, for whom, and does "public" mean "fair game"? Record what you found in Step 1.

The next cell builds your working table in four moves: 1. Drop exact repeats on the full table, before any column is removed. This order matters. While the username, link, and time are still there, a row only counts as a repeat if all of them match: the same post, read twice. Once those columns are gone, two different people who wrote "Same." would look identical. 2. Keep only the columns you chose, as a copy (Pandas 02's rule: never change the raw data). 3. Make one text column, textclean. Glue the text columns together, then collapse runs of spaces, tabs, and line breaks into single spaces, like the collector's normalizewhitespace. The columns you listed stay in the table, untouched, so you can always compare. 4. Rename the columns listed in NEWNAMES. Renaming columns. A scraper's names describe the web page's code, not your data. Naming a column is a small act of interpretation: calling reviews-cards (4) "rating" is a claim about what it holds, so check the values first. Clear names also make the file readable to the next person who opens it (including you, at capstone time). The structure: python mydf = mydf.rename(columns={"oldname": "newname", "otherold": "othernew"}) - The dictionary has the same shape as Pandas 02's .replace({...}): old on the left, new on the right. .replace() changes values in the cells; .rename(columns=...) changes the column names. - Columns that aren't in the dictionary keep their names. - Like most pandas methods, it hands back a new table, so save it with mydf = .... Gluing columns is new. You've seen + join two strings ("Fort" + " " + "Worth"). It does the same for two columns, row by row. The structure: python mydf["newcolumn"] = mydf["firstcolumn"] + " " + mydf["secondcolumn"] - Row by row, the value in firstcolumn, a space, and the value in secondcolumn become one string. - Both columns must hold text. Ours do, because Step 2 read every cell as text. - The loop below does this once per column in TEXTCOLUMNS, so one column or three both work.

# 📖 READ THIS ONE: drop repeats, keep your columns, build one clean text column, rename
def normalize_whitespace(text):
    # .split() with no argument splits on ANY run of spaces, tabs, or line breaks;
    # " ".join() glues the pieces back together with single spaces
    return " ".join(str(text).split())

Step 6: Remove Leftovers ✏️

Fill in the two lists from what you saw in Step 5, run this cell and the next, then read Step 7's sample. Change the lists and re-run as many times as you like: the next cell always starts again from Step 4's table, so nothing gets removed twice. - REMOVEPHRASES: bits of page text to cut out of every row, like "See more". The next cell drops junk rows with a loop over JUNKTEXTS. Each pass is the boolean filtering from Pandas 01, with != (not equal) instead of >. The structure: python mydf = mydf[mydf["columnname"] != "unwanted value"] - mydf["columnname"] != "unwanted value" is True for every row that isn't the unwanted value. - The outer mydf[ ... ] keeps only the True rows, so the unwanted ones are left out. - Run it once per unwanted value (that's what the loop does), and each pass removes one more.
