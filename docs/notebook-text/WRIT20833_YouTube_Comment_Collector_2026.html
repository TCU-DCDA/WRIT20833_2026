Public Comments Are Still Human Expression

Before collecting anything, think about what you're about to collect. Each comment is a person saying something, usually quickly, usually to the other people watching that video, never to you. - Public isn't the same as fair game. Anyone can read these comments, but that doesn't erase your obligations to the people who wrote them. They didn't agree to be part of a class project. - Comments aren't public opinion. The people who comment are a small, self-selected slice of the people who watched, and the people who watched are a slice of everyone who cares about the topic. A news channel's audience, a comedian's audience, and an activist's audience will argue about the same law in different ways. - The sort order chooses for you. "Most relevant" is YouTube's ranking: it favors comments with lots of likes and replies, and the formula is secret. "Most recent" favors whoever posted last. Neither one is a random sample, and neither one is representative. Name the one you used in your writeup, because it shapes what you find. - Computers miss context. Sarcasm, irony, in-jokes, quotes from the video, and cultural references are easy for a person to catch and hard for VADER or a topic model to catch. - The archive has already been edited. Commenters delete comments, channels moderate them, and YouTube filters spam. What you collect is what survived, on the day you collected it. What this notebook does about it. It keeps no usernames and no channel IDs. It collects only what your analysis needs. When you write about your data, prefer patterns and paraphrase over long verbatim quotes: a quoted comment can be pasted into a search engine and traced back to its author, even without a username. Quote only when the exact words matter to your argument. This is the course's standing question in a new place: what does this flatten, who chose it, and can you trust it?

Step 4: From a Link to a Video ID

YouTube identifies every video by an ID of 11 characters, the part after v= in a normal link. The API wants the ID, not the whole link. Links come in several shapes, so this function uses string methods you already know (in, .split(), len()) to find the ID in any of them.

# 📖 READ THIS ONE: pull the 11-character video ID out of a YouTube link
def get_video_id(url):
    url = url.strip()

    if "youtu.be/" in url:                  # short links: youtu.be/ID
        video_id = url.split("youtu.be/")[1]
    elif "/shorts/" in url:                 # Shorts: youtube.com/shorts/ID
        video_id = url.split("/shorts/")[1]
    elif "/live/" in url:                   # livestreams: youtube.com/live/ID
        video_id = url.split("/live/")[1]
    elif "/embed/" in url:                  # embedded players: youtube.com/embed/ID
        video_id = url.split("/embed/")[1]
    elif "v=" in url:                       # normal links: youtube.com/watch?v=ID
        video_id = url.split("v=")[1]
    else:                                   # maybe it's already just the ID
        video_id = url

    # Links often carry extras after the ID ("&t=30s", "?si=abc"); cut them off
    for separator in ["&", "?", "#", "/"]:
        video_id = video_id.split(separator)[0]

    if len(video_id) != 11:
        raise ValueError(f"Couldn't find a video ID in {url!r}. Paste the full link from your "
                         "browser's address bar (or the Share button) into VIDEO_URL in Step 2.")
    return video_id

Step 5: Asking YouTube for Data

Every request to the API is a web address plus some parameters: which video, how many results, what order. That makes a parameter set a dictionary. YouTube answers with a dictionary too, often with lists and dictionaries nested inside it. The function below sends one request and hands back the answer. Most of its lines handle things going wrong (no internet, a bad key, comments turned off, the daily quota used up) and turn YouTube's technical error codes into plain-English messages.

def ask_youtube(endpoint, params):
    params = dict(params)            # a copy, so the key is never added to the caller's dictionary
    params["key"] = API_KEY
    api_usage["requests"] += 1

    try:
        response = requests.get(API_URL + endpoint, params=params, timeout=30)
    except requests.RequestException:
        # Don't show the original error: its text includes the request's web address, which holds your key
        raise RuntimeError("Couldn't reach YouTube. Check your internet connection "
                           "and run the cell again.") from None

    if response.status_code == 200:
        return response.json()

    # Something went wrong: find YouTube's reason code(s) and translate them.
    # "details" holds the more specific codes, so check those first.
    try:
        error = response.json()["error"]
    except (ValueError, KeyError):
        error = {}
    reasons = []
    for item in error.get("details", []) + error.get("errors", []):
        reasons.append(item.get("reason", ""))

    explanation = f"YouTube returned an error (HTTP {response.status_code})."
    for reason in reasons:
        if reason in FRIENDLY_ERRORS:
            explanation = FRIENDLY_ERRORS[reason]
            break
    # Always add YouTube's own words and which request failed: they help you (or your instructor) diagnose it
    raise RuntimeError(f"{explanation}\n\nYouTube's own words: {error.get('message', 'no details given')}"
                       f"\n(request: {endpoint}; reason code: {', '.join(reasons) or 'none'})")

Step 6: Collect the Comments

YouTube hands out comments in pages of up to 100. Each answer includes a nextPageToken, a bookmark you send back to get the next page. When an answer has no bookmark, you've reached the end. Here's the shape of one comment thread in YouTube's answer, trimmed down. These are placeholders, not a real comment: {"id": "Ugx…", "snippet": {"totalReplyCount": 3, "topLevelComment": {"id": "Ugx…", "snippet": {"textOriginal": "(the comment's words)", "publishedAt": "2025-07-08T14:02:11Z", "likeCount": 12, "authorDisplayName": "(the commenter's name)", …}}}, "replies": {"comments": [ …up to 5 replies… ]}} The answer includes the commenter's name. We deliberately don't copy it, as the next cell shows.

# 📖 READ THIS ONE: turn one comment from YouTube's answer into one row for our table
def make_row(comment, is_reply, reply_count):
    snippet = comment["snippet"]
    text = snippet.get("textOriginal") or snippet.get("textDisplay") or ""
    return {
        "comment_id": comment["id"],
        "video_id": VIDEO_ID,
        "video_title": VIDEO_TITLE,
        "comment_text": text,
        "published_at": snippet.get("publishedAt", ""),
        "like_count": snippet.get("likeCount", 0),
        "reply_count": reply_count,
        "is_reply": is_reply,
        "parent_id": snippet.get("parentId"),   # only replies have a parent; None otherwise
        # No author name, channel, or profile picture: we don't need them, so we don't keep them.
    }


# A dictionary can't hold the same key twice, so storing rows by comment_id prevents duplicates
collected = {}


def add_row(row):
    """Add a row unless we already have that comment. Returns True if it was new."""
    if row["comment_id"] in collected:
        return False
    collected[row["comment_id"]] = row
    return True
# 🔧 PLUMBING: fetch ALL of one thread's replies (a thread's answer includes at most 5)
def get_all_replies(parent_id, still_needed):
    replies = []
    page_token = None
    while len(replies) < still_needed:
        params = {"part": "snippet", "parentId": parent_id,
                  "maxResults": 100, "textFormat": "plainText"}
        if page_token:
            params["pageToken"] = page_token
        answer = ask_youtube("comments", params)
        for reply in answer.get("items", []):
            replies.append(reply)
        page_token = answer.get("nextPageToken")
        if not page_token:
            break
    return replies

The main loop. Read it slowly: it's a while loop around a for loop, plus a few ifs. 1. Ask for a page of comment threads. 2. For each thread, add the top-level comment. If you asked for replies, add those too. 3. Stop when you have enough comments, or when YouTube has no more pages.

# 📖 READ THIS ONE: the collection loop
collected.clear()          # start fresh if you run this cell twice
duplicates_skipped = 0
page_token = None
page_number = 0

if INCLUDE_REPLIES:
    parts = "snippet,replies"
else:
    parts = "snippet"

while len(collected) < NUMBER_OF_COMMENTS:
    params = {"part": parts, "videoId": VIDEO_ID, "maxResults": 100,
              "order": SORT_CODES[SORT_ORDER], "textFormat": "plainText"}
    if page_token:
        params["pageToken"] = page_token
    answer = ask_youtube("commentThreads", params)
    page_number = page_number + 1
    new_on_this_page = 0

    for thread in answer.get("items", []):
        if len(collected) >= NUMBER_OF_COMMENTS:
            break
        top_comment = thread["snippet"]["topLevelComment"]
        total_replies = thread["snippet"].get("totalReplyCount", 0)

        if not add_row(make_row(top_comment, False, total_replies)):
            duplicates_skipped = duplicates_skipped + 1
            continue                       # already have this thread (and its replies)
        new_on_this_page = new_on_this_page + 1

        if INCLUDE_REPLIES and total_replies > 0:
            replies = thread.get("replies", {}).get("comments", [])
            if len(replies) < total_replies:          # the thread came back short: fetch the rest
                replies = get_all_replies(top_comment["id"], NUMBER_OF_COMMENTS - len(collected))
            for reply in replies:
                if len(collected) >= NUMBER_OF_COMMENTS:
                    break
                if not add_row(make_row(reply, True, 0)):
                    duplicates_skipped = duplicates_skipped + 1

    print(f"Page {page_number}: {len(collected)} comments so far")

    page_token = answer.get("nextPageToken")
    if not page_token:
        print("Reached the end of the comments YouTube will share for this video.")
        break
    if new_on_this_page == 0:
        print("That page held only comments we already had, so we stopped.")
        break

print()
print(f"Collected {len(collected)} comments using {api_usage['requests']} API requests.")
if len(collected) < NUMBER_OF_COMMENTS:
    print(f"(You asked for {NUMBER_OF_COMMENTS}; this is everything that was available.)")
if duplicates_skipped > 0:
    print(f"Skipped {duplicates_skipped} duplicates that YouTube sent more than once.")

Step 8: Clean, Gently

In Pandas 02 you cleaned a messy table. YouTube's comments come back tidier than a scraper's, but not perfect: some comments are only whitespace, and many have line breaks in the middle. What we fix: - Make a new column, commentclean, where runs of spaces, tabs, and line breaks become a single space. commenttext keeps the original exactly as it was posted. - Drop comments that are empty once the whitespace is gone. - Check for repeated comment IDs. There shouldn't be any, but checking is cheap. What we deliberately don't fix: capital letters, punctuation, emoji, "not," "lol," "/s." Compare: | original | "aggressively cleaned" | |---|---| | This is NOT okay!!! 😡 | okay | | Oh great, ANOTHER law. Just what we needed /s | oh great another law needed | (Two invented examples, not real comments.) Lowercasing, stripping punctuation and emoji, and dropping stopwords like "not" turned an angry comment into a mild one and sarcasm into praise. VADER reads capitals, "!!!", emoji, and "not" as signals, so it needs them. HW4's topic modeling does its own heavier cleaning inside that notebook, on a copy, which leaves your saved file untouched.

# 📖 READ THIS ONE: collapse whitespace into a new column; the original stays as it was
def normalize_whitespace(text):
    # .split() with no argument splits on ANY run of spaces, tabs, or line breaks;
    # " ".join() glues the pieces back together with single spaces
    return " ".join(str(text).split())

        if word != "" and word not in STOPWORDS:
            word_counter[word] += 1

word_counter.most_common(10)

Notice: "not" is in that stopword list, which is fine for counting topics but would be a disaster for sentiment. The same word can be noise for one method and signal for another.
